## Deliverables

| Deliverable | File | Contents |
|---|---|---|
| Currency | `crates/core/src/currency.rs` | `Currency` from a static ISO 4217 table, ETB first (11 currencies, exponents 0, 2 and 3). Serialised as its code. |
| Money | `crates/core/src/money.rs` | `Money { amount: i64, currency }` with checked add, subtract and negate only; mixed currencies and overflow are errors. `PositiveAmount` for line amounts. Exact decimal parsing and formatting. JSON as `{"amount": "39.20", "currency": "ETB"}`. |
| IDs | `crates/core/src/ids.rs` | `AccountId`, `EntryId`, `HoldId`, `ClientId` (UUIDv7 only, one canonical text form) and `IdempotencyKey` (1–128 characters from `A–Z a–z 0–9 - _ . :`). |

**Parsing rules** (`Money::parse`): digits with an optional leading `-` and at
most one `.`; at least one digit on each side of the `.`; no leading zeros;
at most the currency's number of decimal places, never rounded; no `-0`, `+`,
spaces or exponents; at most 32 characters.

**Design notes:**

- There is no `impl Add` for money, so `a + b` does not compile. Only the
  checked methods exist.
- `crates/core` stays free of clocks and randomness. It validates UUIDv7 IDs
  but does not generate them; the engine will.
- The scaffold's `AccountId(u128)` is replaced by the new UUIDv7 type. The
  other scaffold types stay until steps 1.05–1.06.

## Testing requirements

| Requirement | Test | Result |
|---|---|---|
| `parse(format(x)) == x` | `parse_of_format_is_identity` (every `i64`, every currency) | Pass |
| Checked add and subtract never panic and error on overflow | `checked_add_matches_wide_arithmetic`, `checked_sub_matches_wide_arithmetic` (compared with `i128`) | Pass |
| Cross-currency operations always error | `mixed_currencies_always_error` | Pass |
| `"0.001"` ETB is rejected | `rejects_invalid_amounts` | Pass: `TooManyDecimals { max: 2 }` |
| `"-0"` is rejected | `rejects_invalid_amounts` | Pass: `NegativeZero` |
| `i64` max and min boundaries | `handles_i64_boundaries` | Pass: both format and parse back; one santim beyond overflows |

Other property tests: JSON round trip, parsing never panics on any string,
`PositiveAmount` accepts exactly the positive amounts, UUIDv7 IDs round-trip
through text, non-v7 UUIDs are rejected, ID and idempotency key parsing never
panic.

In total: 33 tests (21 unit, 12 property).

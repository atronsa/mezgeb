## Implementation tasks

| Task | Where |
|---|---|
| `currencies` | Table with the 11 ISO 4217 currencies of `crates/core` |
| `accounts`: status CHECK, non-negative totals, no negative normal-side balance unless `allow_negative` | `accounts` CHECKs, including `accounts_not_negative`; also `accounts_closed_at_zero` and the `accounts_guard` trigger |
| `journal_entries`: `UNIQUE(client_id, idempotency_key)`, `UNIQUE(reverses_entry_id)` | Both present |
| `journal_lines`: `amount > 0`, side CHECK, currency FK, balance-after columns | All present; the currency FK is composite with the account, so a line's currency must be its account's |
| Deferred trigger rejecting unbalanced entries | `mezgeb_check_entry_balanced()` on both entries and lines |
| Triggers rejecting UPDATE and DELETE on entries and lines | `mezgeb_reject_change()`, plus TRUNCATE |
| Roles and privileges | As specified; `mezgeb_app` may UPDATE only `debits_total`, `credits_total`, `version` and `status` |

Added beyond the list: the reversal triggers (never reverse a reversal; a
reversal must mirror its original), the open-account check for lines
(INV-24), and the account guard (identity columns immutable, no reopening,
totals never decrease).

## Testing requirements

All run as `mezgeb_app`, each in its own throwaway database.

| Requirement | Test | Result |
|---|---|---|
| An unbalanced insert fails at commit | `unbalanced_entries_fail_at_commit` | Pass: `MZ002` at commit, for an unbalanced entry, a one-line entry and an entry with no lines |
| UPDATE on lines fails | `journal_history_cannot_change` | Pass: `42501` for the app; `MZ001` even for the owner |
| DELETE fails | `journal_history_cannot_change` | Pass: same, and TRUNCATE too |
| Updating `accounts.name` fails due to privileges | `the_app_role_cannot_change_account_identity` | Pass: `42501` |
| A second reversal of the same entry fails | `reversal_rules` | Pass: `23505` |
| Driving a wallet negative fails via the CHECK | `a_wallet_cannot_go_negative` | Pass: `23514` |
| Migration up → down → up works on an empty DB | `migrations_go_up_down_and_up` | Pass |

Other tests: a valid posting commits (the positive control, so failures are
never caused by missing privileges), amounts must be positive, totals only
increase, idempotency keys are unique and well formed, lines need their entry
and their account's currency, account status rules, and the read-only role.
